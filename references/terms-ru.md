# Термины, жаргон, орфография и аббревиатуры

Файл отвечает на вопрос «каким словом назвать понятие и как его написать». Здесь только данные:
правила объясняют RU-02…RU-10 в `rules-ru.md`. Таблицы ниже — дефолты скилла, не стандарт.
Глоссарий проекта переопределяет любую из них.

Порядок работы: глоссарий проекта (§5) → написание из дефолтного глоссария (§2) → класс жаргона
по аудитории (§1) → значение многозначного слова (§6).

## 1. Три класса жаргона

Класс слова определяет аудиторию, для которой слово допустимо (RU-04). Аудитория важнее жанра:
текст для внешних пользователей пишите как документацию, даже если отправляете его в чат.

| Класс | Что это | Где допустимо |
|---|---|---|
| A | Технические существительные без короткого русского эквивалента | Документация для инженеров, чат, тикеты, PR — в одном написании |
| B | Глаголы-кальки с английского | Чат, тикеты, описания PR |
| C | Сниженный жаргон с бытовым значением | Только чат, только при однозначности |

- Если среди читателей есть инженеры вне команды, используйте только класс A и русские глаголы.
- Для внешних пользователей и UI-строк класс A не подходит: пишите только слова из интерфейса.
- «Выкатить» и «откатить» — технические глаголы класса A во всех жанрах. Не заменяйте «выкатите»
  на «разверните» без просьбы пользователя.

### Класс A — технические существительные

Одно написание на весь документ: не чередуйте «бэкенд» и «backend». Род и склонение — в §2.

Класс A по умолчанию: деплой, коммит, ретрай, таймаут, эндпоинт, бэкенд, фронтенд, пайплайн,
фича-флаг, хотфикс, релиз, откат, выкатка, кеш, лог, конфиг, мок, фикстура, стейджинг, прод.

- «ретрай» — или «повтор», если так в глоссарии проекта.
- «хотфикс» — не «горячий фикс» и не «срочный фикс».

### Класс B — глаголы-кальки

Признак кальки: приставка «за-», «от-», «пере-» + английская основа + «-ить» или «-нуть» (RU-04).
Глаголы от терминов («забэкапить», «затегать») — тоже класс B. В чате, тикете и PR держите одно
слово на одну операцию и совершенный вид: не чередуйте «запушьте» и «отправьте в ветку».

| Слово | Замена в документации |
|---|---|
| запушить | отправьте в ветку, отправьте в репозиторий |
| замержить | слейте, влейте в `main` |
| заапрувить | одобрите |
| задеплоить | выкатите, разверните |
| закоммитить | сделайте коммит |
| зареджектить | отклоните |
| заретраить | повторите запрос |
| заребейзить | сделайте ребейз на `main` |
| замокать | подмените моком |
| апдейтнуть | обновите |
| зарепортить, заасайнить | сообщите, назначьте |

- [инструкция; переписывание] Плохо: «Запушьте ветку и заапрувьте PR коллеги» →
  Хорошо: «Отправьте ветку в репозиторий. Одобрите PR коллеги.» — класс B заменён,
  два действия разделены.
- [PR; написание] Хорошо: «Я замержил ветку после повторного прогона тестов.» — в описании
  PR класс B разрешён.

### Класс C — сниженный жаргон

Признак: бытовое слово о технике («тачка», «костыль») или калька без технической операции
(«заюзать»). Бытовые глаголы движения и положения о сервисе («лёг», «висит», «крутится»,
«поднять», «ходить в сервис») — тоже класс C, их замены — в `stop-words-ru.md` §9.

| Слово | Замена вне чата |
|---|---|
| снести, дропнуть, грохнуть | удалите |
| пофиксить | исправьте |
| положили прод | сервис не отвечает |
| тачка | сервер, хост |
| морда | интерфейс, фронтенд |
| костыль | временное решение |
| флапает | работает с перебоями: сервис то отвечает, то нет / тест то проходит, то завершается с ошибкой |
| заюзать | используйте |
| расшарить | откройте доступ |
| раскатать | включите постепенно (или «выкатите», если это выкатка) |

- [wiki; переписывание] Плохо: «Если воркер упал, снесите его под и поднимите заново» →
  Хорошо: «Если воркер завершился с ошибкой, удалите его под. Затем запустите под заново.» —
  два слова класса C и метафора «поднять» заменены буквальными глаголами.

## 2. Дефолтный IT-глоссарий скилла

Форма записи: род, родительный падеж единственного числа, именительный падеж множественного числа.

| Термин | Род и склонение | Пример |
|---|---|---|
| алерт | м., алерта, алерты | Алерт срабатывает через 5 мин. |
| API | нескл., латиницей | Метод API возвращает список заказов. |
| API-ключ | м., API-ключа, API-ключи | API-ключ хранится в Vault. |
| база данных, БД | ж., базы данных, базы данных | Сервис пишет в базу данных `orders_db`. |
| бэкап | м., бэкапа, бэкапы | Сделайте бэкап таблицы. |
| бэкенд | м., бэкенда, бэкенды | Бэкенд отвечает за 50 мс. |
| воркер | м., воркера, воркеры | Воркер читает очередь `orders`. |
| выкатка | ж., выкатки, выкатки | После выкатки проверьте логи. |
| дашборд | м., дашборда, дашборды | Откройте дашборд `notifications`. |
| дедлайн | м., дедлайна, дедлайны | Дедлайн запроса — 2 с. |
| дежурный | м., дежурного, дежурные | Напишите дежурному в чат. |
| деплой | м., деплоя, деплои | Деплой занимает 10 мин. |
| задача (в CI) | ж., задачи, задачи | Задача `build` завершилась с ошибкой. |
| инстанс | м., инстанса, инстансы | Перезапустите один инстанс. |
| кеш | м., кеша, кеши | Кеш очищается раз в час. |
| коммит | м., коммита, коммиты | Сделайте коммит с описанием. |
| конфиг | м., конфига, конфиги | Задайте лимит в конфиге `RATE_LIMITER_LIMITS`. |
| лог | м., лога, логи | Проверьте логи сервиса `orders`. |
| мерж | м., мержа, мержи | После мержа запустите CI. |
| мок | м., мока, моки | Тест использует мок сервиса `notifications`. |
| нода | ж., ноды, ноды | Выведите ноду из кластера. |
| откат | м., отката, откаты | Откат занимает 3 мин. |
| пайплайн | м., пайплайна, пайплайны | Пайплайн запускает тесты после коммита. |
| под | м., пода, поды | Под перезапускается после ошибки. |
| PR | нескл., латиницей | Откройте PR в `main`. |
| прод | м., прода, — | Не запускайте миграцию на проде. |
| ребейз | м., ребейза, ребейзы | Сделайте ребейз на `main`. |
| релиз | м., релиза, релизы | Релиз выкатывается по этапам. |
| реплика | ж., реплики, реплики | Реплика отстаёт на 2 с. |
| ретрай | м., ретрая, ретраи | Клиент делает 3 ретрая. |
| стейджинг | м., стейджинга, — | Проверьте изменение на стейджинге. |
| таймаут | м., таймаута, таймауты | Таймаут запроса — 5 с. |
| тикет | м., тикета, тикеты | Опишите проблему в тикете `PROJ-1234`. |
| токен | м., токена, токены | Токен истекает через 1 ч. |
| трейс | м., трейса, трейсы | Найдите трейс по `trace_id`. |
| фикстура | ж., фикстуры, фикстуры | Фикстура создаёт тестовую базу. |
| фича-флаг | м., фича-флага, фича-флаги | Фича-флаг выключен по умолчанию. |
| фронтенд | м., фронтенда, фронтенды | Фронтенд вызывает API напрямую. |
| хотфикс | м., хотфикса, хотфиксы | Выкатите хотфикс сегодня. |
| чейнджлог | м., чейнджлога, чейнджлоги | Добавьте запись в чейнджлог. |
| эндпоинт | м., эндпоинта, эндпоинты | Эндпоинт `/ping` возвращает `200 OK`. |

Слова, которые дефолтный глоссарий не принимает: «юзер» → «пользователь»,
«джоба» → «задача», «билд» → «сборка», «хендлер» → «обработчик», «продакшен» → «прод»,
«функционал» → конкретная функция (RU-08). Написания: «кэш» → «кеш»,
«тайм-аут» → «таймаут», «бекенд» и «бэк-энд» → «бэкенд».

## 3. Латиница и кириллица

Латиницей пишите:

- имена продуктов, языков и протоколов: Redis, PostgreSQL, Kubernetes, Docker, Go, gRPC
- код, команды, пути, идентификаторы, ключи конфигов, имена веток: `main`, `orders_db`
- аббревиатуры из белого списка: API, CI, PR, JSON, YAML
- клавиши и сочетания: Ctrl+C, Shift+Enter

Кириллицей пишите термины класса A из §2. Не смешивайте два алфавита для одного слова в одном
документе: «деплой» или `deploy`, не оба. Падеж латинского имени задавайте родовым словом (RU-07):

| Плохо | Хорошо |
|---|---|
| в Redis'е, в Редисе | в базе Redis |
| в мастере, в main'е | в ветке `main` |
| PRы, PR'ов | несколько PR, три PR |
| в кубере, в постгресе | в кластере Kubernetes, в PostgreSQL |
| апи, джейсон, ямл | API, JSON, YAML |
| docker-контейнер | Docker-контейнер |

- [README; переписывание] Плохо: «Сохраните конфиг в Редисе и перезапустите под в кубере» →
  Хорошо: «Сохраните конфиг в базе Redis. Затем перезапустите под в кластере Kubernetes.» —
  имена продуктов латиницей с родовым словом, два действия разделены.

Слова с латинской частью пишите через дефис. Регистр латинской части — как у продукта:
«API-ключ», «YAML-файл», «Docker-образ». Дефисное слово — одно слово при подсчёте
(см. `counting.md`). Буква ё — по RU-07: текст без ё в режиме проверки даёт находку
уровня «Мелочь».

## 4. Аббревиатуры

Белый список — аббревиатуры без расшифровки. Латинские: API, HTTP, HTTPS, JSON, YAML, SQL,
URL, CLI, CI, CD, PR, TLS, SSH, DNS, IP, ID, UI, UX. Русские: БД, ПО, ОС, СУБД, ТЗ.
Единицы измерения: с, мс, мин, ч, КБ, МБ, ГБ. Белый список расширяет только глоссарий проекта.

Остальные аббревиатуры расшифруйте при первом упоминании, дальше используйте только
аббревиатуру (RU-10).

- [wiki; написание] Хорошо: «Сервис хранит записи в Redis с ограниченным временем жизни
  (TTL). TTL по умолчанию — 1 ч.» — расшифровка один раз, дальше только аббревиатура.

Написание аббревиатур:

- Латинские аббревиатуры не склоняйте и не пишите с русским окончанием: «в PR», «три PR».
- Русские аббревиатуры БД, ПО, ОС, СУБД, ТЗ не склоняйте: «в БД», «без ТЗ».
- Отраслевые и командные сокращения вне белого списка (RPS, SLA, TTL, ЛК) — только после
  расшифровки или по глоссарию проекта.

## 5. Глоссарий проекта

Глоссарий проекта — главный источник терминов. Найдите его до первого черновика. Источники:
`GLOSSARY.md` в корне проекта, `docs/glossary.md`, `.ste-ru.md`, раздел «Термины» или «Glossary»
в CLAUDE.md, AGENTS.md, CONTRIBUTING.md или README.

Приоритет при конфликте (шаг 2 в SKILL.md):

1. Явное требование пользователя.
2. Обязательные инструкции проекта и ближайшего каталога: CLAUDE.md, AGENTS.md, CONTRIBUTING.md.
3. Специализированный глоссарий: `GLOSSARY.md`, `docs/glossary.md`, `.ste-ru.md`.
4. README.
5. Дефолты скилла: таблицы этого файла.

Непротиворечивые источники объединяйте. Если конфликт меняет результат, задайте вопрос
пользователю. Пример: глоссарий разрешает «ручку» в документации — пишите «ручка».

### Если глоссария нет

Постройте таблицу терминов из самого текста. Три колонки: «Понятие | Встречается как |
Использовать». В режиме проверки покажите таблицу в конце ответа. В режиме переписывания
примените её без пояснений.

Приоритет имени, если в тексте несколько вариантов:

1. Как в коде: имя сервиса, класса, ключа конфига, эндпоинта.
2. Как в UI или в API: подпись кнопки, имя поля ответа.
3. Самое короткое из оставшихся.

Пример таблицы для текста, где один сервис назван тремя словами:

| Понятие | Встречается как | Использовать |
|---|---|---|
| Сервис `rate-limiter` | сервис, служба лимитов, лимитер | `rate-limiter` |
| Повтор запроса | ретрай, повтор, retry | ретрай |
| Ветка по умолчанию | транк, мастер, мейн, main | `main` |

- [тикет; переписывание] Плохо: «Служба лимитов (`rate-limiter`) отдаёт 429, перезапустите лимитер» →
  Хорошо: «Сервис `rate-limiter` возвращает 429. Перезапустите `rate-limiter`.» — один
  термин на понятие, имя как в коде.

Если два имени равноправны и контекст не помогает, задайте вопрос одной строкой после текста.
Не выбирайте сами и не ссылайтесь на «принятый в команде термин».

## 6. Одно слово — одно значение в IT

Многозначность в русском IT-тексте встречается в частых словах, не в редких. Закрепите за таким
словом одно значение на весь документ, другие значения замените буквальным словом (RU-02).
Метафорические глаголы («поднять», «упасть», «висеть») — класс C, см. §1.

| Слово | Единственное значение | Другие значения → замена |
|---|---|---|
| ключ | ключ шифрования, API-ключ, ключ конфига или словаря — всегда с уточнением | ключ команды → «флаг» |
| поле | поле структуры, таблицы или формы | «область» → «раздел», «блок» |
| запись | строка в базе или в логе | «запись в чейнджлоге» → «пункт», «запись экрана» → «видео» |
| сессия | пользовательская сессия с TTL | «созвон» → «встреча», «сеанс отладки» → «отладка» |
| ручка | эндпоинт (чат, тикет, PR) | в документации → «эндпоинт» или «обработчик», «ручной режим» → «вручную» |
| ветка | ветка в репозитории | «ветка кода» (if) → «условие», «ветка обсуждения» → «обсуждение» |
| нода | машина в кластере | «узел» (машина) → «нода», «узел графа» → «вершина», «узел конфига» → «раздел» |
| образ | Docker-образ или образ виртуальной машины | «картинка» → «изображение» |
| хост | машина или адрес сервера | «хост-система» → «сервер» |
| клиент | программа или сервис, который вызывает API | «человек» → «пользователь» |

- Ставьте уточнение у слов с побочным техническим значением (ключ, поле, запись):
  «API-ключ», «поле формы».
- Если значение многозначного слова в исходнике неизвестно, задайте вопрос автору (RU-00).

- [README; переписывание] Плохо: «Сервис ходит в `notifications` по API-ключу из конфига, если
  `notifications` лежит — ретраи не помогут» → Хорошо: «Сервис вызывает `notifications` с API-ключом
  из конфига. Если `notifications` не отвечает, ретраи не помогают.» — метафоры класса C
  заменены, факты те же.
- [чат; написание] Хорошо: «`notifications` упал после выкатки. Я откатил релиз.» — в чате
  «упал» однозначен, класс C здесь допустим.
