# Предупреждения и примечания — RU-28, RU-29

Формулировки правил — в `rules-ru.md`, RU-28 и RU-29. Здесь то, чего в них нет: расширенная
шкала риска, выбор уровня, полные примеры, разметка admonition-движков и чек-лист.
Номера правил STE — в поле «STE:» правил RU-28 и RU-29 и в `ste-mapping.md`. Подсчёт слов — `counting.md`.

## Три блока

| Блок | Когда | Что внутри |
|---|---|---|
| **ПРЕДУПРЕЖДЕНИЕ** | Последствие необратимое или масштабное: потеря данных без бэкапа, простой прода, деньги, безопасность, люди | Команда и последствие |
| **ВНИМАНИЕ** | Последствие восстановимое: нужен откат, повторный запуск, потеря времени на восстановление | Команда и последствие |
| **Примечание** | Риска нет. Информация помогает, но без неё процедура выполнима | Только факты, без команд |

Уровень задаёт последствие, а не слово в исходнике и не английский маркер движка (RU-29).
Один блок — один уровень.

## Какой уровень выбрать

| Ситуация | Последствие, если читатель ошибётся | Уровень |
|---|---|---|
| Удаление таблицы без бэкапа | Данные не восстановить | ПРЕДУПРЕЖДЕНИЕ |
| Рестарт прода в пиковые часы | Пользователи получают ошибки, простой | ПРЕДУПРЕЖДЕНИЕ |
| Рестарт одного инстанса за балансировщиком | Внешних последствий нет | Без блока: обычный шаг |
| Откат миграции, которая удаляет колонку с данными | Данные колонки потеряны | ПРЕДУПРЕЖДЕНИЕ |
| Откат миграции при работающих воркерах | Откат падает, нужен повторный запуск | ВНИМАНИЕ |
| Секрет попадает в лог или в коммит | Утечка, компрометация | ПРЕДУПРЕЖДЕНИЕ |
| Смена пароля закрывает сессии пользователя | Пользователь входит заново | ВНИМАНИЕ |
| Изменение конфига ломает локальное окружение | Окружение пересоздают заново | ВНИМАНИЕ |
| `make regen` перезаписывает правки без коммита | Правки одного человека потеряны, автор вводит их заново | ВНИМАНИЕ |
| Лишний перезапуск: сервис читает конфиг на лету | Ничего не ломается, лишнее действие | Примечание |
| Флаг включает подробный лог | Риска нет | Примечание |

Одно и то же действие попадает в разные строки. Смотрите на последствие в конкретной процедуре, а не на имя команды.
Если сомневаетесь между уровнями, задайте вопрос: «Кто и что теряет?». Правки или время одного человека без коммита (потеря правок, повторный запуск) — ВНИМАНИЕ. Данные прода или пользователей, простой, деньги, безопасность — ПРЕДУПРЕЖДЕНИЕ.

## Структура предупреждения

Порядок «маркер → [условие,] команда → последствие отдельным предложением» и лимит 20 слов
задаёт RU-29. Здесь — то, чего в RU-29 нет:

- Маркер — одно слово заглавными и двоеточие: `ПРЕДУПРЕЖДЕНИЕ:`, `ВНИМАНИЕ:`. Текст после
  маркера — обычным регистром. «Примечание:» — с заглавной буквы, не капсом: это не уровень риска.
- Условие ставьте, только если читатель должен знать его до действия: «Если сервис в проде, …».
  Одно условие, запятая, команда (RU-26).
- Усилитель «обязательно» не пишите: команда в предупреждении и так обязательна.
- Несколько команд — несколько предложений (RU-25).
- Последствие, которого нет в исходнике, не выдумывайте. Оставьте команду и плейсхолдер
  «<уточните последствие>» (RU-00).
- Силу утверждения и хедж не меняйте: «не рекомендуется X» → «Не рекомендуем X», «может
  упасть» → «может упасть» (RU-15). Совет выглядит как запрет — спросите автора.

### Примеры

- [инструкция; переписывание] Плохо: «Важно! Перед тем как дропнуть таблицу `orders_archive`, снимите бэкап, иначе данные не вернуть.» → Хорошо: «ПРЕДУПРЕЖДЕНИЕ: Перед тем как удалить таблицу `orders_archive`, сделайте бэкап. Без бэкапа данные восстановить нельзя.» — Маркер по последствию: данные не вернуть. Последствие отдельным предложением, жаргон «дропнуть» убран.
- [инструкция; переписывание] Плохо: «NB: не рестартуйте `notifications` на проде в пиковые часы — будут пятисотки.» → Хорошо: «ПРЕДУПРЕЖДЕНИЕ: Не перезапускайте `notifications` на проде в пиковые часы. Иначе сервис отвечает ошибками 500.» — Маркер вместо «NB», последствие отдельным предложением. Ошибки 500 на проде — масштабное последствие, поэтому высший уровень.
- [wiki; написание] Факты от автора: откат миграции `0042` при работающих воркерах завершается ошибкой, откат запускают заново. Написано: «ВНИМАНИЕ: Перед откатом миграции `0042` остановите воркеры. Иначе откат завершится ошибкой, и его придётся запускать заново.» — Уровень по последствию: откат повторяют, данные целы — ВНИМАНИЕ. Без таких фактов уровень и последствие не выдумывайте: «<уточните последствие>» и вопрос автору.
- [инструкция; переписывание] Плохо: «Внимание!!! При смене пароля все активные сессии пользователя сбрасываются, предупредите его заранее.» → Хорошо: «ВНИМАНИЕ: Перед сменой пароля предупредите пользователя. Смена пароля завершает все его активные сессии.» — Команда встала первой, «!!!» убраны, последствие — отдельным предложением.
- [README; переписывание] Плохо: «ВНИМАНИЕ: после изменения `RATE_LIMITER_LIMITS` перезапускать сервис не нужно, конфиг подхватывается на лету.» → Хорошо: «Примечание: сервис применяет новое значение `RATE_LIMITER_LIMITS` без перезапуска.» — Риска нет и команды нет — это примечание. Лишний маркер обесценивает настоящие предупреждения.
- [инструкция; переписывание] Плохо:

  ```
  3. Выполните `terraform destroy -target=module.orders_db`.
     Важно: перед этим снимите снапшот, команда удаляет базу вместе с данными.
  ```

  Хорошо:

  ```
  ПРЕДУПРЕЖДЕНИЕ: Перед тем как выполнить команду, сделайте снапшот `orders_db`. Команда удаляет базу вместе с данными.

  3. Выполните `terraform destroy -target=module.orders_db`.
  ```

  Блок стоял после шага: читатель узнал о риске, когда база уже удалена. Теперь блок перед шагом, команда первой.

## Где стоит предупреждение

- Блок стоит перед своим шагом (RU-29). Не после шага и не внутри шага.
- Не дублируйте предупреждение текстом шага. Шаг — действие, блок — риск и команда-защита.
- Одна опасность на весь раздел — один блок перед первым шагом раздела.
- В чате и тикете маркер не обязателен, порядок обязателен (исключение RU-29).
- В описательном тексте предупреждений нет. Если описание само содержит риск, напишите его как факт: «Команда удаляет данные без подтверждения». Блок ставьте в процедуре, которая выполняет команду.

## Что не предупреждение

| Похоже на предупреждение | На самом деле | Куда |
|---|---|---|
| Совет: «лучше запускать с `--dry-run`» | Полезная альтернатива без риска | Примечание или шаг с «можно» |
| Предел: «таймаут не больше 30 с» | Ограничение параметра | В шаг, сразу после действия |
| Информация: «миграция идёт до 10 мин» | Факт | Примечание |
| Результат: «сервис ответит `200 OK`» | Ожидаемый результат шага | Второе предложение того же шага (см. RU-25) |
| Предусловие: «нужен доступ к Vault» | Требование до начала | Раздел «Перед началом» или первый шаг |
| Запрет без последствия: «не трогайте прод» | Риск не назван | Шаг «Не …» или блок с «<уточните последствие>» |

## Примечание (RU-28)

Что можно и чего нельзя в примечании — RU-28. Тест на спрятанный шаг: прочитайте процедуру без
примечаний. Если её нельзя выполнить правильно, в примечании спрятан шаг, предел или риск.
Достаньте его, поставьте на место и повторите тест.

- [инструкция; переписывание] Плохо: «Примечание: обязательно укажите `--dry-run`, если запускаете скрипт впервые.» → Хорошо: «2. Если запускаете скрипт впервые, укажите `--dry-run`.» — Команда в примечании — это шаг. Он получил номер и место в процедуре, условие встало первым.
- [инструкция; переписывание] Плохо: «4. Задайте `timeout`. Примечание: значение `timeout` не должно быть больше 30 с.» → Хорошо: «4. Задайте `timeout`. Максимальное значение — 30 с.» — Предел встал вторым предложением шага, примечание исчезло.
- [wiki; переписывание] Плохо: «Примечание: обратите внимание, что миграция `0042` идёт до 10 мин.» → Хорошо: «Примечание: миграция `0042` идёт до 10 мин.» — «Обратите внимание» — команда-идиома. Факт сам по себе и есть примечание.

## Запрещённые маркеры и обороты

| Не пишите | Почему | Пишите |
|---|---|---|
| «Важно», «Важно!» | Не сообщает уровень | ПРЕДУПРЕЖДЕНИЕ или ВНИМАНИЕ по последствию; без риска — Примечание |
| «NB», «P.S.», «Кстати» | Приписка, которую пропустят | Шаг или блок на своём месте |
| «ОСТОРОЖНО», «ОПАСНОСТЬ» | Шкала физической безопасности (см. ниже) | ПРЕДУПРЕЖДЕНИЕ или ВНИМАНИЕ |
| «ЗАПРЕЩАЕТСЯ» как маркер | Запрет — это команда, а не уровень | «Не …» внутри блока любого уровня |
| «!!!», «Внимание!!!» | Эмоция вместо последствия | Маркер с двоеточием, последствие отдельным предложением |
| «рекомендуется», «желательно», «стоит» | Безличный совет | «Рекомендуем …» (RU-15) |
| «не рекомендуется», «не стоит», «нежелательно» | Безличный совет | «Не рекомендуем …», силу не повышайте (RU-00). «Не делайте …» — только если в исходнике запрет |
| «следует», «не следует» | Не ясно, правило это или совет | В шаге — императив или «Не + императив», в описании и совете — «Рекомендуем / Не рекомендуем» (RU-15) |
| «во избежание …», «чтобы не …» внутри команды | Прячет последствие | «Иначе …» отдельным предложением |
| «будьте аккуратны», «будьте внимательны» | Не действие | Что сделать или чего не делать |
| «непредсказуемые последствия», «могут быть проблемы» | Не называет результат | Что именно сломается или потеряется |
| «Обратите внимание» в примечании | Команда-идиома | Убрать, оставить факт |

## Разметка

Уровень задаёт текст, а не синтаксис движка. Сохраняйте два уровня и примечание в любой разметке.

| Уровень | GitHub Markdown | YFM / Diplodoc | MkDocs Material | Plain text |
|---|---|---|---|---|
| ПРЕДУПРЕЖДЕНИЕ | `> [!CAUTION]` | `{% note alert "Предупреждение" %}` | `!!! danger "Предупреждение"` | `ПРЕДУПРЕЖДЕНИЕ:` |
| ВНИМАНИЕ | `> [!WARNING]` | `{% note warning "Внимание" %}` | `!!! warning "Внимание"` | `ВНИМАНИЕ:` |
| Примечание | `> [!NOTE]`; совет — `> [!TIP]` | `{% note info %}`; совет — `{% note tip %}` | `!!! note`; совет — `!!! tip` | `Примечание:` |

- На GitHub `CAUTION` строже `WARNING` — обратно шкале STE. Выбирайте по нашему уровню, а не по английскому слову.
- GitHub рисует свой заголовок (Caution, Warning). Маркер в тексте блока не повторяйте. В YFM и MkDocs укажите русский заголовок в кавычках.
- Совет — вариант примечания: полезная альтернатива без риска. Текст пишите по правилам примечания.
- Если проект уже использует свои врезки, оставьте их. Текст внутри пишите по этим правилам.
- Markdown без врезок (README, runbook): маркер заглавными с двоеточием, полужирный допустим: `**ВНИМАНИЕ:** текст`. Точку после маркера не ставьте.
- Блок между шагами нумерованного списка пишите с отступом пункта. Без отступа нумерация начнётся заново (пример — `genres.md`, §5).
- Plain text (чат, тикет, сообщение об ошибке): маркер заглавными, двоеточие, текст обычным регистром.

## Другие шкалы: ISO 3864 и ГОСТ

Слова ОПАСНОСТЬ, ПРЕДУПРЕЖДЕНИЕ, ОСТОРОЖНО (ISO 3864-2, ГОСТ IEC 82079-1) — шкала для этикеток и физической безопасности.
ГОСТ Р 2.601-2019 использует ПРЕДУПРЕЖДЕНИЕ, ВНИМАНИЕ, ЗАПРЕЩАЕТСЯ. Порядок «блок перед шагом, команда первой, последствие отдельным предложением» — решение ste-ru по STE 7.2–7.3, а не цитата ГОСТ.

Распознавайте эти слова в исходниках. В IT-тексты чужую шкалу не вносите. «ОСТОРОЖНО» → ВНИМАНИЕ или ПРЕДУПРЕЖДЕНИЕ по последствию. «ОПАСНОСТЬ» → ПРЕДУПРЕЖДЕНИЕ.
Если проект документирует оборудование по ГОСТ, следуйте требованиям проекта: они выше правил скилла.

## Чек-лист

- Маркер выбран по последствию, один на блок.
- После маркера — условие (когда оно есть) и команда в повелительном наклонении.
- Последствие — отдельным предложением, конкретное.
- Блок стоит перед шагом.
- Каждое предложение ≤20 слов. В примечании ≤25.
- В примечании нет команд, пределов и рисков.
- Процедура без примечаний выполнима.
